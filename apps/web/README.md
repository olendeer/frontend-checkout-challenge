# Фронтенд магазина

Каталог, корзина, оформление, оплата тестовой картой и наличными при получении.
Next.js 16 (App Router), TypeScript, TanStack Query.

Условия: [задание](../../docs/ASSIGNMENT.md) · [интеграция](../../docs/INTEGRATION.md) ·
[критерии](../../docs/EVALUATION.md).

## Запуск

Из корня репозитория, после `npm ci`, в двух терминалах:

```sh
npm run dev        # бэкенд, http://localhost:4000
npm run dev:web    # фронтенд, http://localhost:3000
```

Адрес API берётся из `NEXT_PUBLIC_API_URL`. Если бэкенд поднят на другом порту, скопируйте
`apps/web/.env.example` в `apps/web/.env.local` и поправьте значение.

```sh
npm run build:web       # сборка
npm run start:web       # запуск собранного
npm run typecheck:web   # tsc --noEmit
npm run test:web        # юнит-тесты (vitest)
npm run e2e:web         # сквозные сценарии (playwright)
```

Для e2e один раз нужен `npx playwright install chromium` — API и фронтенд Playwright поднимает
сам.

## Как устроено

Слои лежат в `src/`, зависимости направлены внутрь: `core → data → domain → features`.

```
core/      HttpClient, HttpError, Endpoint, журнал идемпотентности, хранилище;
           adapters/fetch — единственное место с fetch во всём приложении
data/      endpoints.ts — единственное место с URL; репозитории, dto/ собирает сущности
domain/    без React: entities/*.entity.ts (данные + правила) и *.service.ts
query/     кэш серверного состояния: <область>/*.queries.ts, ключи, клиент
features/  экраны: *.module.tsx + *.hooks.ts
providers/ сборка графа зависимостей, доступ к сервисам через useXxxService()
ui-kit/    Button, TextField, Fieldset, Alert, Modal, …
```

Поток данных: `страница → модуль фичи → *.hooks.ts → useXxxService() → доменный сервис →
репозиторий → HttpClient`. Компонент в сеть не ходит, заголовки не собирает и ошибки не
разбирает.

Каждая обязанность меняется отдельно и без правок в экранах: новый запрос — строка
в `data/endpoints.ts`, метод репозитория и хук в `query/<область>/*.queries.ts`; общие
заголовки, авторизация и повтор на `401` — `fetch.adapter.ts`, разбор конверта ответа — его же
метод `_toResponse`; тело ошибки разбирает `api-error.dto.ts`, а текст для пользователя берётся
из таблицы кодов в `domain/errors/error-message.ts` — экран получает его готовым через
`getErrorMessage(error)`, ошибки полей уезжают в форму через `applyFieldErrors`.

Устойчивость собрана из шести вещей: ключ идемпотентности хранится вместе с отпечатком тела,
поэтому повтор того же заказа не создаёт второй; на `401` адаптер один раз пересоздаёт сессию и
повторяет запрос; заказ и незавершённую оплату страница читает с сервера по URL, так что
перезагрузка ничего не теряет; при `CART_VERSION_CONFLICT` расчёт повторяется с актуальной
версией корзины, при `QUOTE_EXPIRED` перечитывается, не стирая форму; опрос идёт, только пока
`order.isPaymentPending`; успех показывается по ответу сервера, а не по факту отправки запроса
на оплату.

Агрегации по корзине — одним проходом через `reduce` (`cart.quantityIndex`,
`Product.toStockIndex`), поэтому карточка каталога узнаёт своё количество за `O(1)`. Суммы
всегда берутся из ответа API: считать деньги на клиенте — это второй источник истины.

## Проверенные сценарии

`npm run e2e:web` — 14 сценариев в браузере, все проходят: оплата картой до подтверждённого
статуса, отказ карты и отмена с повторной оплатой, наличные при получении, курьерская доставка
со стоимостью из API, пустая корзина и товар без остатка, двойное нажатие «Оформить»,
перезагрузка во время ожидания оплаты, сбой сети при расчёте, потерянный ответ на создание
заказа, восстановление сессии после сброса токена, проход на 1280 и 390 px и оформление
с клавиатуры.

`npm run test:web` — 22 юнит-теста на доменные правила и мапперы.

## Принятые решения

- **Без UI-библиотеки**: макета нет, вёрстка на SCSS-модулях, значения темы — CSS-переменные.
- **Сущности вместо сырых ответов.** Ответ API не поднимается выше `data`: `dto/` собирает из
  него сущность, и правило живёт рядом с данными — `order.canPay`, `product.maxQuantity`.
- **`query/` — слой кэша, а не папка с хуками.** Корзину читают четыре места; при прямых
  вызовах сервисов это четыре запроса и четыре расходящиеся копии.
- **Валидация — `react-hook-form` + `yup`.** Схема одна, условия описаны через `when`; она же
  работает вне формы — пока адрес не дозаполнен, запрос за расчётом не уходит.
- **Диалог оплаты живёт на странице заказа**, а не на оформлении: так он переживает
  перезагрузку. Сама модалка — нативный `<dialog>`, фокус-ловушка и Esc из коробки.

## Недоработки

- Нет истории заказов: заказ открывается по прямой ссылке после оформления.
- Расчёт обновляется по таймеру раз в 5 минут; отсчёта до истечения и предупреждения нет.
- Ошибка оплаты в диалоге не сбрасывается при повторном открытии.
- Нет тёмной темы и анимаций переходов между состояниями.
- Юнит-тестами покрыт домен, но не React-компоненты — на них смотрят сквозные тесты.
